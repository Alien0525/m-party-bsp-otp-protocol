# Generalized M-Party BSP Protocol for Collision-Free OTP Routing

This repository contains the implementation, visualizer, and headless simulation suite for a novel One-Time Pad (OTP) routing algorithm. The protocol manages asynchronous, collision-free message routing for an arbitrary number of parties (m-parties) over a shared, finite 1D array using a static Binary Space Partitioning (BSP) tree structure.

## The Problem

In a traditional, static OTP allocation over a shared array of N pads, dividing the space equally among m-parties results in strict bounds. If one party experiences high network traffic (a single-sided flood), it quickly exhausts its localized pad allocation and deadlocks, while the remaining array sits entirely unused. 

This protocol introduces dynamic array re-indexing and paired-jumping to allow active parties to scavenge unused pad space from silent parties without violating strict security/delay buffers.

## Algorithm Mechanics

The implementation relies on several core mathematical constraints and routing rules:

### 1. The Grid and Delay Constraints
The shared resource is an array of size `N`. To prevent asynchronous packet collision, a strict delay buffer `d` must be maintained between any two facing parties at all times.

### 2. M-Party Scaling and Ghost Anchors
The system accepts any arbitrary number of parties `m` and mathematically scales the active arena to the next power of 2 (e.g., m=5 scales to 8 structural endpoints). Parties are placed in opposing pairs (e.g., Party A faces Party B). 
* Unused structural endpoints are calculated as inactive "dummy nodes."
* When a party is placed on the grid, it drops a "Ghost Anchor." The party's first message consumes this anchor (resulting in 0 positional movement), ensuring boundary limits are mathematically claimed before progression.

### 3. Collision Trigger
As parties step forward to consume pads, the gap between them shrinks. A collision is mathematically triggered the moment the empty space between them evaluates to `<= d`. (This guarantees that `> d` empty pads are strictly preserved). Array boundaries are evaluated conceptually as `0` and `N+1`.

### 4. BSP Tree Landing and Memory Scavenging
Upon collision, the pair halts and initiates a jump sequence:
* The algorithm scans all Active Arenas (the space between the boundaries `0` to `N+1` and the outermost parties).
* It evaluates predetermined midpoints `M` generated by a static BSP tree (N/2, N/4, 3N/4, etc.).
* A jump spot `M` is only valid if it guarantees `> d` empty pads on both the Left and Right sides of the new landing coordinate.
* Once found, the left party lands at `M` and faces left (-1), while the right party lands at `M+1` and faces right (+1). The global array is physically re-sorted.

### 5. Deadlock
If a pair collides and the algorithm scans the entire array without finding a valid BSP jump spot `M` that satisfies the `d` constraint, the protocol halts.

## Headless Simulation and Efficacy

The repository includes a headless Monte Carlo test suite (`test-suite.html`) designed to bypass DOM rendering and calculate array fragmentation over tens of thousands of permutations. 

The test suite measures **Pad Wastage %** (Unused Pads / Total Pads at Deadlock). By evaluating edge cases (Max Jumps / Collision Forcing, No Jumps / Single-Sided Floods, and Pure Random Traffic), the protocol proves it mathematically outperforms the traditional static allocation baseline across all scenarios by dynamically reallocating dead space.
